Промпт для разработки микросервиса: "Обработчик биржевых данных"
1. Название микросервиса: OrderBook-Indicator-Processor

2. Цель: Создать высокопроизводительный микросервис на Python, который в реальном времени получает поток данных о стакане ордеров (order book) с криптовалютной биржи, рассчитывает на его основе заданные технические индикаторы и сохраняет результаты в базу данных ArangoDB.

3. Основные требования:

Подключение к источнику: Микросервис должен подключаться к WebSocket API биржи (например, Binance, Bybit) для получения потока данных по указанной торговой паре (например, BTC/USDT).
Динамическая конфигурация: Параметры для расчета индикаторов (список индикаторов и их настройки) должны передаваться в сервис при запуске или через отдельный API-endpoint, а не быть зашитыми в коде.
Расчет индикаторов: На основе данных из стакана (например, средневзвешенной цены) должны рассчитываться технические индикаторы.
Сохранение в ArangoDB: Результаты расчетов (значения индикаторов) вместе с метаданными (тикер, время) должны сохраняться в виде документов в указанную коллекцию ArangoDB.
4. Входные данные:

Источник: WebSocket stream с данными стакана ордеров.
Формат (пример JSON от биржи):
{
  "e": "depthUpdate",     // Event type
  "E": 1672515782136,     // Event time
  "s": "BNBBTC",          // Symbol
  "U": 157,               // First update ID in event
  "u": 160,               // Final update ID in event
  "b": [                  // Bids to be updated
    [
      "0.0024",           // Price level to be updated
      "10"                // Quantity
    ]
  ],
  "a": [                  // Asks to be updated
    [
      "0.0026",           // Price level to be updated
      "100"               // Quantity
    ]
  ]
}
5. Конфигурация индикаторов:

Сервис должен принимать на вход JSON-объект следующей структуры, который определяет, какие индикаторы и с какими параметрами нужно считать:

Пример файла config.json:
{
  "symbol": "BTCUSDT",
  "db_collection": "technical_indicators_stream",
  "indicators": [
    {
      "name": "RSI",
      "enabled": true,
      "params": {
        "length": 14
      }
    },
    {
      "name": "MACD",
      "enabled": true,
      "params": {
        "fast": 12,
        "slow": 26,
        "signal": 9
      }
    },
    {
      "name": "BBANDS",
      "enabled": false,
      "params": {
        "length": 20,
        "std": 2.0
      }
    }
  ]
}
6. Логика обработки:

При старте сервис читает файл конфигурации.
Подключается к WebSocket-потоку для указанного symbol.
Агрегирует данные из потока для формирования свечей или использует средневзвешенную цену (VWAP) по стакану для расчетов.
Для каждой новой свечи (или через заданный интервал времени) рассчитывает все индикаторы, у которых enabled: true.
Формирует документ и отправляет его в ArangoDB.
7. Структура документа для сохранения в ArangoDB:

Документы должны сохраняться в коллекцию, указанную в db_collection.

Пример документа:
{
  "_key": "BTCUSDT_1672515782136", // Уникальный ключ (символ + timestamp)
  "symbol": "BTCUSDT",
  "timestamp": 1672515782136,
  "indicators": {
    "RSI_14": 62.5,
    "MACD_12_26_9": {
      "macd": 150.75,
      "histogram": 20.15,
      "signal": 130.60
    }
  },
  "metadata": {
    "source": "binance_websocket",
    "processed_at": "2025-09-04T12:00:01Z"
  }
}
8. Технологический стек:

Язык: Python 3.9+
База данных: ArangoDB
Ключевые библиотеки:
python-arango - для работы с ArangoDB.
websockets - для подключения к бирже.
pandas и pandas-ta (или talib) - для расчета индикаторов.
pydantic - для валидации конфигурации.
9. API (опционально, для гибкости):

Реализовать REST API на FastAPI/Flask с двумя эндпоинтами:

POST /config - для динамического обновления конфигурации индикаторов без перезапуска сервиса.
GET /status - для мониторинга состояния (статус подключения, последняя обработанная запись).
